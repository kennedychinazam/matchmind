`request-deadline.mjs` applies a proposed12-second deadline to each provider and database transport request, including its response body. It forwards cancellation, requests transport abort, cleans up timers/listeners, and returns a fixed AbortError on timeout. It does not retry a request; the actual pinned SDK read/write tests verify a timeout is not replayed. Existing explicit provider429 read retries and collector stage budgets remain unchanged. This is a per-transport deadline, not a hard total invocation limit. Abort/timeout never proves a server-side write was cancelled or rolled back. No new provider call, collection window or model/odds/grading rule is introduced. The successful response preserves status, body and quota headers; buffered body length/encoding headers are removed. Staging timing/latency acceptance is required before rollout.

`READ-ONLY-status.sql` reports only named jobs' SQL status/counts and newest edition time. It contains no payloads, cron command text, headers, credentials or raw errors. It was verified read-only against named MatchMind production. `health.mjs` keeps edition freshness, SQL success and exact-request HTTP/collector completion separate. The default600-second edition-age threshold is explicit/configurable operational proposal, not an existing SLA. Invalid/future dates remain unknown; missing HTTP correlation remains unverified. HTTP200 alone cannot hide application rejection, partial writes, warnings, probe/history responses or malformed response fields. Only a matching known request ID with the expected normal collector response can report completed. The projection never returns the underlying provider/error data.

No enqueue wrapper, public RPC, grant, table, retention policy or automatic alert was installed.
