## Confirmed findings

1. **P1: a stalled public read can remain pending indefinitely and consume every retry.** `fixtureAccess()` (3210–3227), `fixtureDisplayLoad()` / `fixtureDisplayAttempt()` (3304–3343) and history page RPCs have no client deadline. `screenPending` deduplicates by screen and is removed only after the promise settles. In the actual-function VM proof an inert never-settling Scores RPC remained pending; the second read made no new RPC and shared the stuck entry. This is a source-controlled indefinite case, not an assertion that a particular hosted request currently hangs. The public shared-record loader similarly holds its one `_engineRecordLoading` promise until settlement (22899–22925).

2. **P1: a later Scores repaint erases the failed-load state and can claim an empty date.** `scoresReadFailed()` (23252) puts its failure only in DOM text. `renderScores()` (23363) replaces that text with “No matches on this date” when an existing cache has an empty list, or “No matches today” when the cached list has no selected-date rows. The actual render function transformed a synthetic failed-load message into “No matches on this date.” This can follow a failed refresh of an existing empty cache, or a date/filter repaint after the failure. Empty, pending, failed and last-known states need durable resource metadata; DOM text is not state.

3. **P1 public provenance: cloud Scores alone can still leave the header saying Sample data.** Initial markup is “Sample data” (627). `refreshDataChip()` (3990) checks publication/league state but never successful Scores state; `afScoresFromCloud()` (23267–23302) does not correct the badge after accepting its own envelope. The actual helper VM, with one cloud Scores row and no Analysis leagues, retained “Sample data.” A failed Analysis read can instead set the one global badge to Unavailable while independent Scores are valid. The badge should describe the active public resource, and the sample label should require an explicit sample choice.

4. **P1 recovery gap: reconnect/foreground does not retry failed independent public feeds.** There is no `online` event handler in current source. The foreground handler at27027 invokes `loadCloudResults()` and Scores only when Scores is active. That result-hydration call updates scores/grades for already-known fixtures; it does not reload the Analysis prediction/history pair or shared-record resource. More's shared record retries on tab reopening (19082), and `renderMoreRecord()` retries by ten-minute age (23603). Staying on a failed More/Analysis page through reconnect or background/foreground can therefore leave the failure until navigation/manual action. Existing source-expiry and result hydration rules must remain separate from retry policy.

5. **P2 race: obsolete public failures can write current-resource UI.** `loadFixturePresentation()` captures its client/owner/epoch inside `try`, validates before success adoption, but its `catch` (3483–3513) cannot consult that local context and can clear/annotate the newer current view. `loadSharedRecords()` has one global flight and no context-scoped commit fence. `fixtureTable()` rejects obsolete replies, but its old caller's catch still publishes a failed global record. This is a source-confirmed missing error-commit fence, not a claimed cross-account private-row leak. Tests should exercise account/client/epoch switches and later success before an older failure.

## Existing safeguards to retain

- Analysis predictions and paged immutable history are an edition-matched pair; retries for edition movement are bounded to four attempts. Do not adopt a shortened/mismatched archive merely to show a nonempty screen.
- A previously accepted Analysis edition survives a failed refresh only until its own `expires_at`; its age is disclosed. Expired editions are not newly admitted. Scores already carries independent edition age/expiry text when rows render. Do not silently turn either policy into unrestricted stale-data admission.
- The no-source cold Scores path already resolves to unavailable rather than permanent loading. Existing fixtures/consumer tests protect raw-source fences, original probability vectors, unknown-field rejection, history continuity and filter recovery.
- Existing AUD-09 tests distinguish dated empty issued Tips markets from failed/missing issue reads. Keep these semantics; broader market/settlement changes remain MM-17. Do not create, reprice or grade claims as part of a read/retry fix.
- Retained Lean data's edition/failure consumption deserves a later MM-11 parity review; no Lean/model change is proposed here.
