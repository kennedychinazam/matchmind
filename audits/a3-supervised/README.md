# Single-fixture A3 supervised preparation — research only

The separately versioned, Santos-only capacity-risk extension is documented in
[CAPACITY-EXCEPTION-IMPLEMENTATION.md](CAPACITY-EXCEPTION-IMPLEMENTATION.md).
It is an explicit unverified-capacity exception, never a verified token bound.
Its optional isolated SQL installation is separate from `installSingle`; no
genuine exception or final authorization is created by installing the code.

This additive controller prepares one GPT-6 Luna independent A3 comparison using
the accepted `a3-workflow`. It preserves the original Sunday controller, source
collector, executor, model contracts and database writer. It does not deploy,
publish, place bets or relax A4. There is no automatic dispatch CLI or retry loop.

## Source and unchanged engine

`collectOneFixture(id)` uses only the existing public read-only Data API client.
It admits an upcoming source-listed fixture on October27–31, collects the complete
fixed **55-competition** Build355 history at the actual 60-month cutoff, and
retains the selected future target. Per-competition counts before/after, keyset
pages, source-body hashes, receipt/server clocks, nulls, status and all existing
football fields are retained. Count drift, incomplete inventory or target changes
reject the export. Required history is never truncated. This is an as-collected,
non-atomic read, not a claim of upstream atomicity or first historical availability.
Only fixtures and shared statistical measures are read; no new source or service
is integrated. Odds and engine predictions are not requested for AI input.

The trust boundary for upstream identity is the approved HTTPS collector operated
by the trusted research operator. Source metadata strings or a database receipt
alone cannot prove remote-provider authenticity. The operator must enroll the
actual collected object and retain its genuine page receipts, not fabricate a
`collection.kind` field. Injected readers are marked synthetic and cannot use
`enrollOne`. `enrollOne` declares a distinct one-request research study and appends
the source and job to the **existing** isolated journal. No reservation is made.

The additive `enrolledSource` adapter in A3 authority loads the immutable packet
through the pinned local repository, verifies its study/fixture/content binding,
and mints a source capability. The repository checks the pinned image, Unix
socket and network-none container; its own SQL transport ignores caller SQL
functions. It is not a generic JSON `verified` flag. Source receipt establishes
availability by enrollment, not before an earlier match. The accepted A3 football
projection still rejects extra/aliased/nested odds/model fields and post-cutoff
results, and preserves missingness and source limitations. `certified_prospective`
stays false on the accepted packet contract; real receipt provenance and eventual
issuance are separate records, not a silent change to A4 certification.

Run the unchanged `runEngine({...source,receipt_at_utc})` after job enrollment.
`prepareOne(packet,engine,profile,now,{catalog})` checks its pinned Build355 source
hash, complete input hash, fixture orientation, original timestamp, eligibility
and probabilities. A real source requires a real engine clock. The complete
catalog snapshot must bind the frozen model profile. No engine probabilities or
recommendations enter `body.messages`; they remain downstream comparison data.

## Local-only additive schema

`singleStore(db)` accepts only the existing isolated database boundary and fixed
`matchmind_restore`/`matchmind_test` names. An actual preparation must restore/use
the accepted latest shared ledger; it must never start an empty financial ledger.
The original 3,404-event identity/parent/body-hash/receipt anchor is checked before
paid admission. The static anchor contains no private bodies or financial rows.
The owned store object is frozen and recognized through an opaque capability;
an arbitrary object cannot authenticate genuine operator receipts.

`local.sql` adds a narrowly dated study-declaration function and a private,
immutable operator-receipt table. `attempts.sql` adds an immutable **study-level**
one-attempt latch. Neither changes the original `weekend_append` function, its
Sunday study policy, the existing ledger, quota lock or $5 ceiling. New tables
are private/RLS-protected; anon, authenticated and shadow_runner cannot invoke
the declaration/approval/reservation functions. Apply only to disposable research
or the isolated restored private database, never hosted Supabase.

Final authorization and independently reviewed provider-bound evidence are
separate receipts. Only the trusted operator can record them. Authorization
binds job, fixture, UTC issuance date, packet/request/model/backend, exact maximum
new liability, final operator-message hash, short expiry and key/workspace-bound
BYOK evidence. A receipt does not magically prove that its human-reviewed content
is true: do not insert hypothetical token counts or a placeholder review hash.
Current preparation creates **neither** authorization nor readiness receipts.

## Dispatch gates and one-attempt behavior

`dispatchOne(plan,options)` requires an owned plan and, for genuine sources, the
owned repository, verified recovery/external copy and explicit supervision.
Before any reservation it requires immutable final authorization and a separate
request/profile/schema-bound reviewed readiness artifact. No caller flag replaces
these receipts. The reviewer must establish a complete input bound and supported
schema/output contract. Metadata/byte estimates alone are not automatically
promoted into this gate.

At admission, after checkpoint, and immediately before HTTP, revalidate:

- Explicit October27–31 issuance date, authorization/BYOK expiry, source earliest
  receipt and full-history freshness; strict kickoff-minus-450-seconds deadline.
- Exact fixture identity, status and kickoff from a fresh approved read.
- Actual restricted-runtime enforcement, current revision/secret observations.
- GPT-6 Luna/OpenAI routing, stable endpoint safety contract and pricing. Transient
  latency/throughput/uptime metadata does not change the safety contract. Context,
  physical output, max-prompt limit, parameters, tier, status, pricing and no
  implicit caching do. No external tools, search, cache controls or fallback.
- Fresh authenticated dedicated-key/account metadata and existing BYOK validation.
- Original ledger ancestry, every retained liability, known billing, no global
  halt, account headroom and the shared lifetime ceiling. Actual costs already
  covered by retained holds are not subtracted twice.

The reviewed complete input upper bound must not exceed the actual endpoint's
max-prompt cap or context minus physical output maximum. The currently observed
Luna endpoint has a 922,000-token max prompt, 1,050,000 context and 128,000 physical
output cap. Proposed response budget is 4,096. Local JSON validity and a generous
byte estimate do not prove exact provider framing/tokenization or output adequacy.
No private evidence is sent to an external counter during preparation.

After all gates, the additive atomic reservation function locks the **existing**
quota row, checks immutable authorization/readiness/deadlines, rejects any attempt
under the study even when the request hash changes, then calls the unchanged
ledger writer and commit-confirmation function. Deadline checks before transaction
completion prevent late authorization from committing a new hold. The latch and
the financial event commit together. Concurrent attempts cannot produce two holds.
The financial ledger remains the original reservation events, not the latch table.

The pre-HTTP checkpoint is mandatory. A private opaque permit is minted only
after it succeeds and gates pass again. Consumption deletes the permit atomically
and returns a frozen detached projection; it cannot be reset, mutated or reused.
The genuine transport refuses synthetic/unenrolled sources. Its final deadline
also includes UTC midnight, source/operator/account/fixture clocks and kickoff;
elapsed asynchronous metadata work is rechecked. Curl uses inherited proxy/CA,
HTTPS only, no redirects/retries, one pinned completion path and a bounded timeout.

A raw response is retained before strict A3 parsing. Forecast/abstention, source,
prompt, schema, request, model, generation, risk and uncertainty identities are
appended immutably and checkpointed. Malformed/refused/truncated responses remain
failures; no baseline fallback is scored as AI. Failed/ambiguous attempts or
checkpoint failures retain liability, halt and never retry. The separate risk
assessment does not change probabilities; no multiplier, averaging or value pick.

## Current preparation versus live readiness

Actual fixture/source/engine checks, private financial aggregates, checkpoint
receipts and the exact proposed request identity are in the private Director
report, not public Git. An initial full-history identity-policy failure and a
different candidate outside Build355's unchanged 72-hour window were retained as
preparation failures, not model abstentions or paid forecasts. No historical rows
were removed and no accepted text policy or engine window was weakened.

The selected candidate passes the source packet and unchanged engine checks.
Authenticated endpoint metadata verifies the pinned profile/pricing and local
schema matches documented structural requirements, but a complete authoritative
token/framing bound and exact schema/output readiness are **not** established.
Therefore no readiness receipt was manufactured and no final paid authorization
is requested while this blocker remains. Source/runtime/account/operator evidence
also expires: a recent fixture read cannot refresh the older complete history.

This is a working, tested controller with genuine preparation evidence, not a
claim of new AI inference, calibrated probabilities or readiness obtained through
configuration flags. Keep PR6 draft. Stop for Director review.
